Custom Skills
Save a reusable prompt as a markdown file that runs with a single /command.
Why for you: 'Watch the build' is your only workflow so far, and you repeated it 3 times in 3 days. A /watch-build skill would give the same efficient polling and the same final report every time.
mkdir -p .claude/skills/watch-build && cat > .claude/skills/watch-build/SKILL.md <<'EOF'
---
name: watch-build
description: Watch the current CI build until it finishes and report the result
---
1. Find the latest run: `gh run list --limit 1 --json databaseId,status,name`
2. Block on it with one command: `gh run watch <id> --exit-status`. Do NOT poll repeatedly.
3. If it failed, run `gh run view <id> --log-failed | tail -50`.
4. Report: PASS/FAIL, workflow name, duration, and the failing step with its key error lines and a suggested fix.
EOF

Parallel Agents Triage Every Failing Job
When a CI pipeline breaks in several places, parallel sub-agents could each investigate one failing job at the same time, whether lint, unit tests, integration tests, or packaging. A coordinating agent would then merge their findings, remove duplicate root causes, and propose one combined fix. A failure that touches many jobs could be triaged in a few minutes instead of one log at a time.
Getting started: Use Claude Code's Task tool to launch sub-agents, one per failing job, with `gh run view --log-failed` or your CI's API as the data source.
PASTE INTO CLAUDE CODE:
List all jobs in the latest CI run and identify every failed job. For each one, spawn a separate sub-agent using the Task tool. Each sub-agent should fetch only that job's failed logs, find the root cause, and return: the job name, the key error lines, the suspected cause, a confidence level, and a proposed fix. When all sub-agents report back, merge their findings, group failures that share a root cause, rank the fixes by impact, and apply the top fix. Then retrigger the pipeline and report which jobs should now pass.
